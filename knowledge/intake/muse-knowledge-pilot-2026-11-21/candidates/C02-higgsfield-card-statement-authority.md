# 判断事例 C02：金額の正本は「領収書メール」とは限らない（Higgsfield の事例）

## Evidence（証拠）

| 項目 | 内容 |
|---|---|
| evidence class | REAL（Gmail 実メールで観測） |
| observed_at | 2026-11-21 |
| scope | 経理シートへの計上（Higgsfield） |
| 事実 | Higgsfield には領収書メールが存在しない。金額の根拠は、別アカウント宛ての楽天カード利用お知らせメールだった（Ultra 年間プラン ¥137,550、利用日 2026-10-30、ほか Plus 月額 ¥9,715、少額 ¥164）。10月に $756 オファー適用をサポートへ交渉したが不成立のため、提示額ではなくカード請求額が正しい金額 |
| source | 楽天カード利用お知らせメール（isamu.watanabe.mobile@gmail.com 宛）／ サポート交渉メール |

## 観察（何が起きたか）

- 当初、領収書メールが見つからず金額未確定として扱いかけた。
- 実際にはカード会社の利用通知メールに確定情報があり、それを正本として経理シートへ計上できた（弥生インポート対象に反映済み）。
- 教訓： **証拠の探索は「発行体の領収書」だけに固定しない。カード明細・利用通知が正本になるサービスがある。提示額・交渉額ではなく、実際の請求額を採用する。**

## Recommendation（推奨）

- 金額未確定の支出を見つけたら、探索順序を「領収書メール → カード利用通知メール → 請求確定メール」とし、最初に見つからなくても未確定で止めない。
- サービスごとに「正本になる資料の種類」をメモしておく（例： Higgsfield ＝ 楽天カード利用お知らせメール）。
- 交渉・オファーの金額は証拠にしない。請求額のみを計上根拠にする。

## Policy Candidate（候補）

| | 内容 |
|---|---|
| current | 領収書メールがなければ金額未確定として保留 |
| proposed | カード利用通知・請求確定メールまで探索し、請求額が確認できればそれを正本として計上する。探索しても見つからない場合のみ未確定とする |
| rationale | 未確定のまま滞留する支出を減らし、経理の網羅性を上げるため |

## Safety Floor チェック

- 推測金額での計上は引き続き禁止（本候補は「探索範囲を広げる」もので、「推測を許可する」ものではない）。
- 円金額が資料で確認できないものは弥生インポート用へ入れないルール（K02 §6）は不変。
