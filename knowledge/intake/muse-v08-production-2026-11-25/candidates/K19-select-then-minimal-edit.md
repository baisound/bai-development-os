# 当たり個体の選別＋設計正本の照合＋単一パスの局所編集

## 要旨

生成物の正史違反（目の色、形見の意匠）は、**1枚の画像を編集で直し続ける**方法では解決しなかった。解決したのは次の3段である。

1. **選別**：一から生成を複数回し、正史に最も近い「当たり個体」を選ぶ（編集の土台は作るのではなく選ぶ）。
2. **照合**：残りの違反は、生成物の見た目ではなく**設計文書（正本）まで遡って**正解を確定する。
3. **最小編集**：当たり個体に対して、変更点を列挙し「他は一切変えるな」を併記した**単一パスの局所編集を1回だけ**行う。編集の重ねがけ（チェーン）はしない。

## なぜ従来の方法が失敗したか（試行の記録）

対象の条件（共通）：1792×1008の実写風静止画、虹彩は半径およそ7px、焚き火の暖色照明。モデルは特記なき限り gpt-image-2。

- **後付けの色修正（K14試行A〜D）**：文章指示の全体編集は両目が赤化／赤茶化。プログラム的リカラーは拡大すると皮膚・白目へ滲んだ（オーナー却下）。生成した虹彩だけを切り取って合成する移植方式も、輪郭が壊れて却下。
- **チェーン編集（編集結果への再編集）**：目が成立した個体でも、頬に白いムラ・波（モアレ状の劣化）が出た。オーナーが「重ねがけは劣化する」と見抜き、以後は**毎回、原版または選別した個体からの単一パスだけ**をルール化。
- **単一パスの全体編集の繰り返し（試行G系）**：右目の色指定（「青・琥珀・灰ではなく黒」）を足す等の工夫をしても、右目が青・青緑・グレーに流れる失敗が続いた。文章の空間指定の弱さは解消しなかった。
- **一から生成の目当て（試行F1〜F3）**：構図は良いが、うつむき・横顔で目が見えない、両目の色分けが曖昧、など目の成立は運任せだった。

## 成功した手順（#33での実施記録）

1. **物差しを先に作る**：「良い目」を感覚で判定しない。原画（四面図P00）の顔アップから正本の左目を切り出して拡大し、参照として手元に置く。あわせて色を数値で測る方法を用意する（虹彩まわりの平均色と、最も暗い部分の色。最も暗い部分まで赤い＝瞳が無く塗りつぶし、と判定できる）。
2. **一から生成で個体を選ぶ**：参照渡し生成（キャラシート3枚＋原画の目アップを参照に追加）を複数回回す。F4で「構図が台本どおり・左目が赤・右目が原画どおりグレー寄りの暗色」の個体が得られ、これを土台に選んだ。目を編集で作るのではなく、**目が成立している個体を選ぶ**のが要点。
3. **残りの違反は設計文書で正解を確定する**：右下の形見（割れた紋章板）は、生成物の見た目では「丸紋で何となく合っていそう」に見えた。しかしオーナーの「これは誰の品か」という問いから設計文書（武器設計U94）を引くと、正解は「レンの大盾『黒牙』の紋章板＝鉄紺の円板に金の牙2本、割れると1本ずつ」で、丸紋は主人公の家紋に近い別物だった。**形見・紋・意匠は、持ち主から逆算し、設計文書で裏を取る**。見た目のそれらしさで採用しない。
4. **単一パスの局所編集を1回だけ**：土台F4に対し、変更点2件（紋章板を鉄紺＋金の牙に／紫の布を畳まれた帯に）を列挙し、「人物・顔・目・衣装・焚き火・背景・構図・色味は一切変えるな」を併記して1回だけ編集。2サンプルとも他部が保たれ、オーナーが牙の立体感のある方（F4i_1）を採用した。
5. **検証は拡大＋数値＋全体の3点セット**：顔と品は拡大クロップ、目は色の数値、全体は構図と劣化（ムラ・波）の有無。合格したものだけをオーナー判断に上げる。

## 再現条件と注意

- 局所編集が他部を保てた条件：土台が生成画で、変更対象が画面の端の小物に限局し、変更内容が具体的（材質・色・図柄・状態を名指し）だった。変更が顔などの中心部に及ぶ場合は同条件にならない。
- 当たり個体が出るまでの生成回数は運に左右される（今回は目のためだけで一から生成6回、編集試行は10回超）。「回す→測る→捨てる」の監査を速く回す前提の手順であり、1回の生成で決める方法ではない。
- 編集モデルを変える案（Nano Banana Pro等）も検討したが、APIは無料枠がなく請求アカウントの復旧が前提のため未実施。手順自体はモデル非依存で、編集段だけ差し替え可能。
- 検証で不合格なら採用せず、理由を記録して捨てる（K14の原則を継続）。
