# TASK-004 P0.0 — Repository / Product Boundary Correction

## Decision

BAI Development OS is a standalone product and must not be developed as a subsystem of `javascript-roulette`.

## Corrected ownership

### BAI Development OS

Owns reusable governance, Roles, Context Guard, Lifecycle, registries, schemas, templates, OS source, OS tests, and TASK-004 onward.

Canonical root:

```text
/home/baisound/bai-development-os
```

### JavaScript Roulette

Owns its application source and project-local TASK-001 through TASK-003 evidence.

Canonical root:

```text
/home/baisound/projects/javascript-roulette
```

Its BAI Development OS integration is a thin `.bai-os/project.json` adapter.

## Git lineage

The former `/home/baisound/projects/ai-team` Git repository becomes the history-bearing base of `bai-development-os`. The later Context Guard/Lifecycle implementation and TASK-004 evidence previously committed under `javascript-roulette` are imported with provenance rather than pretending they originated in the former workspace repository.

## GitHub target

Rename:

```text
baisound/ai-team
```

to:

```text
baisound/bai-development-os
```

`baisound/javascript-roulette` retains its name.

## Failure lesson

The previous product boundary made a consumer project the host of its own development operating system. This created circular ownership, project-specific hardcoding in generic code, duplicated governance artifacts, ambiguous task ownership, and unnecessary context/governance overhead. Product-boundary validation is therefore a regression requirement.
